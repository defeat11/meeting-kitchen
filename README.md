# meeting-kitchen

[English](README.en.md)

**ضغطة زر على تابلت في غرفة الاجتماعات ← طلب على شاشة المطبخ ورسالة في Power Automate.**

> **هذا النظام يعمل في بيئة إنتاج لدى جهة عملي، والكود ملكها. هذا المستودع يوثّق المعمارية والقرارات الهندسية وطريقة البناء.**

نظام ضيافة كامل في 5,851 سطراً: تطبيق PWA لتابلت الغرفة، وواجهة PHP فيها 15 نقطة نهاية،
وشاشة مطبخ حيّة، وتطبيق أندرويد بخدمة أمامية للتنبيه، و Webhook إلى Power Automate.

الاستضافة مشتركة: PHP و SQLite فقط. لا Node، ولا WebSocket، ولا خدمة إشعارات سحابية.
كل قرار في النظام مبني داخل هذا القيد.

---

## المشكلة

طلب الضيافة في اجتماع يمرّ بشخص. الموظف يخرج من الغرفة، أو يتصل، أو ينتظر.

واستدعاء الدعم الفني أسوأ: لا سجل لوقت الطلب، ولا لمن استلمه.

المطلوب: زر واحد داخل الغرفة. ووصول مضمون للمطبخ حتى لو الشاشة مطفأة أو الشبكة انقطعت.

---

## كيف يشتغل

| المكوّن | الوظيفة |
|---|---|
| تابلت الغرفة (PWA) | شاشة طلب بلا تسجيل دخول. معرّف الغرفة محفوظ محلياً، فكل طلب موسوم بغرفته |
| العمل بلا إنترنت | Service Worker يخزّن الواجهة. الطلب أثناء الانقطاع يدخل طابوراً محلياً ويُرسل عند العودة |
| واجهة PHP | ملف واحد بنمط `?action=`، و 15 إجراءً، و 6 جداول SQLite. كل استعلام فيه مُدخل مستخدم يمرّ بعبارة مُجهّزة (22 عبارة)، والباقي SQL ثابت بلا تركيب نصوص |
| شاشة المطبخ | تسحب `feed` كل 5 ثوانٍ بمؤشر `after`، فلا ينزل إلا الجديد والنشِط. صوت واهتزاز عند الوصول |
| تطبيق أندرويد | WebView وخدمة أمامية تسحب كل 8 ثوانٍ، وتُظهر إشعاراً نظامياً والشاشة مطفأة |
| **Power Automate** | كل استدعاء يُطلق Webhook من الخادم بحمولة `{type, label, room, note, time}` |
| الواجهة | عربي أولاً (RTL) وإنجليزي كامل: 182 مفتاح ترجمة في ملف واحد |

**مسار الاستدعاء إلى Power Automate:**

```
تابلت الغرفة ──POST action=call──> PHP API ──INSERT──> SQLite
                                      │
                                      ├──> شاشة المطبخ + تطبيق أندرويد (سحب feed)
                                      └──> POST JSON ──> Power Automate (HTTP trigger)
                                                              └──> Teams / بريد / مهمة
```

عنوان الـ Flow محفوظ في جدول `settings`، ويُعدَّل من شاشة إعدادات المطبخ.
لا يوجد في أي ملف كود، ولا على أي تابلت.

## أهم قرار في التصميم

**المشكلة:** الاستدعاء يجب أن يصل إلى Power Automate. لكن نداء HTTP إلى سحابة خارجية قد
يتأخّر أو يفشل. لو انتظره الخادم، يبقى الموظف واقفاً أمام زر معلّق.

**القرار:** الخادم يحفظ الاستدعاء في SQLite أولاً، ثم يُطلق الـ Webhook داخل `try/catch`
بمهلة اتصال ثانيتين ومهلة كلية 3 ثوانٍ. فشل الـ Flow لا يغيّر رد الواجهة إطلاقاً.

**التكلفة والعائد:** أسوأ حالة 3 ثوانٍ إضافية على طلب واحد. مقابلها: الاستدعاء محفوظ
وظاهر على شاشة المطبخ حتى لو كان Power Automate خارج الخدمة تماماً.

قاعدة البيانات هي المصدر الموثوق. الـ Flow قناة تنبيه إضافية، لا شرط نجاح.

ونفس السبب جعل الإطلاق من الخادم لا من المتصفح: عنوان الـ Flow لا ينزل إلى تابلت في غرفة مفتوحة.

## ماذا في هذا المستودع

الكود ملك جهة العمل، فليس هنا. المستودع يوثّق المعمارية وطريقة البناء والنشر.

بنية النظام في الإنتاج:

```
htdocs/
  index.html app.js kitchen.html kitchen.js settings.html settings.js
  config.js styles.css manifest.json sw.js icons/
  api/  index.php  db.php  data/   ← يُنشأ عند أول طلب، محميّ بـ .htaccess
```

طريقة النشر كما تتم فعلاً:

1. رفع الملفات إلى جذر استضافة مشتركة. قاعدة البيانات تُنشأ وتُبذَر تلقائياً عند أول زيارة.
2. فتح `settings.html` على التابلت، تحديد اسم الغرفة، وتثبيت الصفحة على الشاشة الرئيسية.
3. لا كلمة مرور في الكود: تُضبط `KITCHEN_USER` و `KITCHEN_PASSWORD` في البيئة، أو يولّد
   النظام كلمة عشوائية تُكتب مرة واحدة في ملف يُحذف بعد أول دخول.
4. لصق عنوان الـ Flow في تبويب الإعدادات — من هذه اللحظة كل استدعاء يصل إلى Power Automate.

وقبل كل رفع تمرّ الملفات ببوابة تحقق آلية: PHP lint لكل ملف خادم + فحص صحة كل JSON، ولا يُرفع شيء إلا بعد `VERIFY: PASSED`.

## لماذا بنيته

أعمل مشرف تقنية معلومات، وطلبات غرف الاجتماعات كانت تصلني شفهياً أو متأخّرة.

الآن الاستدعاء الواحد يصل إلى 3 وجهات: شاشة المطبخ، وإشعار الجوال، و Power Automate.
